# ActiveSessionViewV3 — BentoUI-Rewrite + Performance-Fix

Ziel: `ActiveSessionViewV3.swift` von Grund auf neu, BentoUI-idiomatisch (Showcase-Pattern), mit **identischem Funktionsumfang** wie V2 — aber ohne das Lag beim Satz hinzufügen/entfernen/moven.

## 0. Root-Cause Performance-Fix (ohne den alles laggt weiter)

**Problem:** `WorkoutService.getTopSet` und `.getRecentWorkingStats` rufen bei JEDEM Aufruf `sessions.fetchAll()` auf (komplette Session-Historie + alle Sets aus der DB). Beide werden (a) pro Übung in `recache()` und (b) **inline im body** via `SetRecommendationService.recommend(...)` aufgerufen — also N × 2 Full-DB-Fetches bei jedem Body-Rebuild.

**Fix — mehrschichtig:**

1. **Per-Session-Cache im `WorkoutService`** (`WorkoutService.swift`):
   - Neuer privater Cache `private var topSetCache: [UUID: SetEntry]` + `private var workingStatsCache: [UUID: ExerciseWorkingStats]`, geleert beim `finishSession`/`cancelSession`.
   - `getTopSet(for:)` und `getRecentWorkingStats(for:)` liefern den Cache-Wert, falls vorhanden, sonst einmal fetchen + cachen.
   - Dadurch entfällt das wiederholte Full-DB-Fetchen innerhalb einer aktiven Session. Diese Methoden werden von *vielen* Screens (Analytics, PRs, MuscleRanking) benutzt — der Cache ist ein sicherer, globaler Win, kein Verhalten-Change.

2. **`ActiveSessionViewModel` (`@Observable`)** statt `@State groups`-Snapshot:
   - Hält die gruppierten Exercises + Sets, **empfiehlt einmal pro Load/Mutation** (nicht im `body`) und cached `recommendation` + `topSetSummary` pro Exercise.
   - Mutationsmethoden (`addSet`, `duplicateLastSet`, `toggleComplete`, `deleteSet`, `moveExercise`, `removeExercise`, `recomputeVolume`) invalidieren selektiv statt Full-`recache`.

3. **Debounced `context.save()`** statt Save bei jedem Tap:
   - `addSet`/`deleteSet`/`toggleComplete` mutieren das `@Bindable`-Modell sofort (UI ist sofort responsive via `@Observable`) und schedulen einen Save über `Task { try? await Task.sleep(for: .milliseconds(250)); save() }` (jeweils vorab `saveTask?.cancel()`).
   - Lifecycle-Grenzen (`finish`/`cancel`/`dismiss`/.`onDisappear`) forcieren einen finalen synchronen Save.

4. **Entfernen inline-recompute im body:** `recommend(...)` wird **nicht** im `body` gerufen. Die Recommendation liegt auf dem VM pro Exercise vor; das Badge liest nur den gecachten Wert.

## 2. UI — Layout (BentoUI, nach BentoUnifiedShowcase)

Root: `BentoScreen(scrolls: true) { VStack(spacing: theme.spacing.sm) { ... } }.bentoActionBar { ... }`

Im trailing-slot: `BentoIconButton("play.fill")` (Play-Mode), `BentoButton("Fertig", variant: .primary)`. Leading: `BentoIconButton("xmark")` → Menü (Abbrechen/Schließen). 2. **Hero-Card** — `BentoCard(tone: workoutColor, style: .elevated, padding: .lg)` mit `BentoProgressRing(progress: sessionProgress, tone: .accent, size: 76, label:)` + "X / Y Sätzen erledigt". ersetzt die alte `liveStatsCard`.

## 3. SetRowV3 — Eingaben nach Tracking-Typ

- Nummerierter Check-Circle (komplett = grün, sonst grau) — Toggle via VM.
- `switch type`:
  - `.repsWeight`: zwei `BentoTextField`-ähnliche numerische Felder (Gewicht/Reps) — direktes Binding auf `@Bindable set.weight`/`set.reps` mit `keyboardType: .decimalPad`/`.numberPad` (Muster aus V2, aber stilistisch an BentoTextField angeglichen).
  - `.reps`: ein Feld (Reps).
  - `.duration`: `durationField` (min:sec) — bestehendes Hilfs-Widget.
  - `.distanceDuration`: Distanz + Dauer.
- `.repsWeight`: Assist-Toggle (Person-2-Icon) → `assistedReps`-Feld einblenden.
- Tracker-Play (`.duration`/`.distanceDuration`): `BentoIconButton("play.fill")`.
- Trash: `BentoIconButton("trash", variant: .ghost)`.
- Komplett-Sätze: `BentoCard`-Hintergrund in `tone: .success` niedriger Opacity.
- **Performance:** `SetRowV3` ist `Equatable` (struct, alle Felder Value-Type außer das `@Bindable set` → ich nutze `set.id` + relevante Werte in einer `equatable`-Equiv-Methode), damit SwiftUI bei `.onChange(of: session.sets.count)` nicht jede Zeile neu baut.

## Randbedingungen

- Kein Drag-Reorder (User-Wahl: Menü hoch/runter).
- `WorkoutService`-Cache ist additiv (keine API-Änderung, nur internes Memoizing) → sicher für alle anderen Call-Sites.
- Bestehende Services (RestTimer, ExerciseTrackerService, WorkoutLiveActivityManager, ElapsedTimer, FinishSessionSheet, ExerciseLibraryView, ExerciseDetailsSheet, ExerciseTrackerView) werden **weiterverwendet**, nicht dupliziert.
- V2-Datei bleibt bestehen als Sicherheits-Netz, wird nur nicht mehr referenziert.
- Alle neuen Sheets via `.bentoSheet`, Run-Screens via `.fullScreenCover`.
