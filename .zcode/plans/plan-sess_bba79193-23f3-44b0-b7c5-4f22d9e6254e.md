# Habit-Routinen Feature

Neue "Routinen" = geordnete Abläufe von Habit-IDs, die man als geschlossene Einheit schnell abarbeiten kann (z. B. "Morgenroutine"). **Keine Änderung an bestehenden `@Model`-Klassen** — nur additive neue Modelle/Services/Views gemäß `HOW_TO_MODIFY_SWIFT_DATA.md`.

## 1. Neues Modell: `HabitRoutine` (additiv, keine Migration)

**Datei:** `ThriveWood/Data/Models/HabitRoutineDomain.swift` (neu)

- `@Model final class HabitRoutine` mit:
  - `id: UUID`, `title: String`, `iconSystemName: String`, `colorRaw: String` (HabitColor), `habitIDs: [UUID]` (geordnete Liste — bewahrt die Reihenfolge), `sortOrder: Int`, `createdAt: Date`
  - alle nicht-optionalen Properties mit **Inline-Default** (Pflicht laut HOW_TO)
  - Typed-Accessor `color: HabitColor` (wie HabitGroup)
  - `var habits: [Habit]` ist **keine** SwiftData-`@Relationship` — wird zur Laufzeit per Repo-Join aufgelöst (reine ID-Liste, wie vom User gewünscht)
- Registrierung in `SharedModelContainer.swift`: `HabitRoutine.self` zur `Schema([...])` hinzufügen

## 2. Auto-Cleanup: archivierte/gelöschte Habits aus Routinen entfernen

- **Neues Repo:** `SwiftDataHabitRoutineRepository` (in `Data/Repositories.swift`) nach dem Vorbild von `SwiftDataHabitGroupRepository` (`fetchAll`, `fetch(id:)`, `create`, `update`, `delete`, `addHabit`, `removeHabit`, `reorder`, plus `pruneArchived(_ activeHabitIDs:)`).
- **Neues Protocol** `HabitRoutineRepository` in `Helpers/Protocols.swift`.
- **Cleanup-Einhänge-Punkt:** In `SwiftDataHabitRepository.archive(_:)` und `.delete(_:)` (Repositories.swift, Zeilen 56–64) nach dem bestehenden `try save()` einen Aufruf ergänzen, der die gelöschte/archivierte Habit-ID aus allen `HabitRoutine.habitIDs` entfernt. Da das reine ID-Arrays sind, ist das ein sicheres, nicht-invasives `removeAll { $0 == habit.id }` über alle Routinen. → erfüllt "wird automatisch rausgenommen".
- `AppEnvironment.swift`: `let routineRepo: any HabitRoutineRepository` hinzufügen + instanziieren (`SwiftDataHabitRoutineRepository(context:)`).

## 3. UI: eigener "Abarbeiten"-Screen (BentoUI)

**Neue Datei:** `ThriveWood/Views/Home/Routines/RoutineRunView.swift`

- Voll-BentoUI-Screen (`BentoScreen` + `BentoPageHeader`), fullScreenCover-präsentiert vom HomeView.
- Header zeigt Routine-Name + Gesamtfortschritt (`BentoProgressRing` oder `BentoProgressBar` X/Y erledigt).
- Liste der Routinen-Habits als große `BentoCard`s mit dem gewohnten Toggle-/Increment-Verhalten (Wiederverwendung der `BentoHabitRowView`-Logik bzw. direkte `env.habitService.toggle/increment/decrement`-Aufrufe).
- Wenn alle Habits erledigt sind: Erfolg-Zustand + Auto-Dismiss (mit kurzer Verzögerung + Haptik).
- Braucht ein kleines `@Observable RoutineRunViewModel` (neu in gleicher Datei) für `completedIDs`, `progress` pro Habit — analog zu `HomeViewModel`'s Toggle-Logik.

**Neue Datei:** `ThriveWood/Views/Home/Routines/RoutineEditorSheet.swift`

- `.bentoSheet` zum Erstellen/Bearbeiten: Name, Icon, Farbe, und eine Multi-Select-Liste der aktiven Habits (via `BentoSelectionChips` oder `BentoListRow`-Checkboxen), die die `habitIDs`-Reihenfolge aufbaut. Speichern via `routineRepo`.

## 4. Einhänge-Punkt im HomeView

- Im `HomeView` (oberhalb oder unterhalb der Habit-Liste) eine neue Sektion "Routinen" mit `BentoSectionHeader` + `BentoAdaptiveGrid`/`LazyVStack` aus `BentoCard`s (eine pro Routine). Tap → `RoutineRunView` als fullScreenCover. Plus-Button im `BentoPageHeader`-Trailing-Slot für "Neue Routine" → `RoutineEditorSheet` als bentoSheet.
- Dafür braucht `HomeViewModel` zwei neue Felder/Methoden: `var routines: [HabitRoutine]` (geladen in `load()`), `func loadRoutines()`, `func deleteRoutine(_:)`, `func openRoutine(_:)` (setzt eine `presentedRoutine`-State im View). Die View hält `@State var presentedRoutine`/`editingRoutine`/`showingNewRoutine`.

## Randbedingungen
- Kein `VersionedSchema`/`SchemaMigrationPlan` (rein additives Modell).
- Alle neuen nicht-optionalen Properties mit Inline-Default.
- Alle neuen Sheets via `.bentoSheet`, Run-Screen via `.fullScreenCover`.
- `BodyMeasurementMapView`/andere Maps unangetastet — Scope ist nur Habits.
- Wiederverwendung bestehender Services (`habitService.toggle/increment`) — keine Duplikation der Punkte-Logik.

Build-Prüfung + Commits nach jedem logischen Block (Modell+Repo → UI Run → UI Editor+HomeView).
