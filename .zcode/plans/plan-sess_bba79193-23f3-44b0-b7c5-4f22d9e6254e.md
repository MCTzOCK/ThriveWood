# Companion — Ausbau zum echten Haustier (Voll)

## Status Quo
Aktuell: 1 Bedürfnis (Energie 0–100), feed-Hooks, Evolution, hand-gezeichnete Kreaturen. Keine Sättigung/Hygiene/Aktivität, kein Streicheln, keine Emotionen/Reaktionen, keine Sprechblasen, keine Accessoires.

**Foundation Models / Apple Intelligence ist bereits etabliert** (`AIPlanGeneratorView`, `WorkoutAnalysisView`, iOS 26.4) — Muster mit `LanguageModelSession`, `SystemLanguageModel.default`, `@Generable`, Fehlerbehandlung liegt vor und wird 1:1 für die Sprechblasen adaptiert.

Deine Vorgaben: **Voll** — alle 4 Bedürfnisse (Hunger, Hygiene, Aktivität, Zutrauen), Streicheln, Emotionen/Reaktionen, Sprechblasen via Apple Intelligence (+ Fallback), Accessoires/Items.

---

## Phase 1 — Datenmodell erweitern (additiv, SwiftData)

`CompanionDomain.swift` — neue Properties mit Inline-Defaults an `Companion`:
```
hunger: Double = 80         // 0=verhungert, 100=satt
hygiene: Double = 80        // 0=dreckig, 100=saubermädchen
fun: Double = 80            // 0=gelangweilt, 100=beschäftigt
bond: Double = 20           // 0=Null Zutrauen, 100=tiefe Bindung (startet niedrig!)
lastFedAt, lastCleanedAt, lastPlayedAt, lastPettedAt: Date
coins: Int = 0              // Währung für Accessoires (verdient durch consistency)
lastSpeechAt: Date          // throttle AI-Sprechblasen
ownedAccessoryIDs: [String] = []
equippedAccessoryID: String? = nil
```

Neue `@Model`-Klassen (in `SharedModelContainer` Schema aufnehmen):
- `Accessory` (id, rawID, name, cost, slotRaw, assetRaw) — Katalog-Build + User-Besitz
- Companion-Accessoire-Katalog als statisches `enum AccessoryCatalog` (z.B. Hut, Schal, Ball, Knochen) mit `cost`.

`CompanionStage`/`CompanionMood` bleiben; **Mood wird neu berechnet** aus dem Durchschnitt aller 4 Bedürfnisse + Energie (nicht nur Energie).

## Phase 2 — CompanionService ausbauen

Erweitern:
- `processDayRollover()` zieht jetzt auch hunger/hygiene/fun ab (z.B. −15/Tag).
- `feed()` — kostet Punkte, füllt hunger, leichter bond+.
- `clean()`, `play()`, `pet()` —各自的 Aktionen mit Cooldown + bond+.
- Habit-/Workout-/Tagesziel-/Login-Triggers geben je auch fun/bond/hunger kleinen Boost.
- `buy(accessory:)`, `equip(accessory:)`.
- Mood-Neuberechnung bei jeder Mutation.
- Neue `@Observable`-Snapshots: hunger/hygiene/fun/bond/coins/ownedAccessoryIDs/equippedAccessoryID/lastSpeechAt + ein `speechBubble: String?` für die Live-Sprechblase.

## Phase 3 — Apple-Intelligence-Sprechblasen (`CompanionSpeechService`)

Neuer Service `ThriveWood/Services/CompanionSpeechService.swift`:
- `func nextSpeech(for companion:) async -> String`:
  - prüft `SystemLanguageModel.default.availability` — falls nicht verfügbar → **Fallback** auf statische Templates aus einem `CompanionSpeechTemplates`-Enum (nach Mood/Bedürfnis kategorisiert).
  - bei verfügbar: `LanguageModelSession(model: SystemLanguageModel.default)` + `@Generable struct CompanionLine { var text: String }`, Prompt mit Kontext (Name, Species, Mood, aktuelles niedrigstes Bedürfnis, Tageszeit), „antwort als süßes Haustier in 1 kurzem Satz auf Deutsch".
  - Throttle: max 1 AI-Call pro ~60s (`lastSpeechAt`), bei nicht-Verfügbarkeit sofort Template.
- Wird aus der CompanionView beim Erscheinen + auf Tap der Sprechblase getriggert.

## Phase 4 — UI: CompanionView zur Haustier-Zentrale ausbauen

`CompanionView` wird zur **Voll-Pflege-Ansicht**:
- **Großes Tier zentral**, darüber schwebende **Sprechblase** (BentoCard-Style mit kleinem Pfeil), tappbar → neue Line.
- **Streichel-Zone**: Tap aufs Tier → `pet()`, löst Haptik (.soft) + Animations-Reaktion (Schnurren/Freude, kurzer Scale-Bounce, Herz-Partikel via `ParticleEffect`/overlay).
- **Bedürfnis-Balken**: 4 gestackte `BentoProgressBar` (Hunger 🍖, Hygiene 🛁, Aktivität 🎾, Zutrauen ❤️) + bestehende Energie.
- **Aktions-Buttons** (BentoButton-Grid): Füttern 🍖, Pflegen 🧴, Spielen 🎾, Streicheln ✋. Jeder zeigt Kosten/Cooldown.
- **Mood-Emotionen**: das Tier reagiert live auf Aktionen (Animation + kurzer Overlay-Emoji wie „💖" beim Streicheln, „😋" beim Füttern).
- **Accessoires-Section**: Shop (verfügbare Items mit Coin-Preis + Kaufen) + Ausgerüstet (Toggle).
- **CompanionKit**: Kreaturen bekommen optionale `accessory`-Parameter (Hut/Schal gezeichnet über dem Körper), `isPetted`-Animation, `reaction`-Overlay.

## Phase 5 — CompanionKit erweitern

- `CompanionCreature` bekommt: `accessory: AccessoryType?` (rendered als overlay Shape), `reaction: ReactionType?` (z.B. `.pets`, `.eats`, `.hearts`), `isHappy: Bool`.
- Reaction-Overlays: Herzen-Partikel beim Streicheln, Futter-Emoji beim Essen, Seifenblasen bei Pflege.
- Mood-Emotionen im Body (Schwanzwedeln bei vibrant, hängende Ohren bei critical).

## Phase 6 — Coins & Accessoire-Shop

- Coins verdienen: +5 pro Habit-Erledigung, +10 pro Workout, +20 Tagesziel. (Parallele Währung zu Punkten — separate Senke für Accessoires, damit der Wald unangetastet bleibt.)
- `AccessoryShopView` (eigene View): Grid verfügbarer Items mit Vorschau (CompanionCreature mit Accessoire), Preis, „Kaufen"/„Ausgerüstet".
- Persistenz der Items im `Accessory`-Modell.

## Phase 7 — Build, Polish, Commit

## Architektur-Prinzipien
- Alles **additiv** (SwiftData Inline-Defaults, keine Migration).
- **Apple Intelligence optional** mit statischem Template-Fallback — läuft auf allen Geräten.
- Wald + bestehende Companion-Mechaniken bleiben erhalten, werden ergänzt.
- CompanionKit bleibt app-unabhängig (Bridge bleibt erhalten).
- Trigger-Hooks an bestehenden 4 Stellen werden erweitert (nicht neu erfunden).
